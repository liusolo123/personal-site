## 设计与实现约束

- 沿用纯 HTML/CSS/JavaScript；不新增框架、构建步骤、第三方运行依赖或在线字体依赖。
- 建议新建 `demo.html`、`css/demo.css`、`js/demo.js`、必要的 `assets/demo/` 本地纹理。可只读复用现有模块；不修改生产 `index.html`、`project.html`、原有 CSS/JS、JSON 或摄影原图，不改部署配置。
- 首屏包含“策展空间”标识、简短说明、同等级的“项目作品 / 摄影作品”入口。桌面双列等宽、预览等高；项目使用真实项目内容和设计过的文字封面，摄影使用现有照片。不得只用摄影作首屏主视觉或把项目缩成导航小字。手机可以调整排列，但两个入口须一开始就可发现。
- 页面结构：简介与双入口 → 精选项目 → 摄影作品 → 关于/页脚。项目至少呈现当前 JSON 中全部项目，包含标题、用途摘要、技术信息和 `project.html?id=...` 真实链接；照片读取当前数据，隐藏朋友类，图片路径与现有资产保持一致。不要虚构项目截图、成果指标或人物信息。
- 视觉：标题宋体/衬线，正文系统无衬线；正文一般 16–18px；主标题各宽度最多两行；窄屏项目英文封面不得裁切。两类作品的标题、入口和展示空间均有足够分量，不追求页高机械相等。
- 背景色：首屏 `#F2F3EF`、项目 `#E5EBE6`、摄影 `#192521`、关于/页脚 `#F2F3EF`；深色正文 `#1C2925`；黄铜点缀 `#C5B58D`。深色区域使用足够明亮的文字。
- 第一层材质为全站一致的静态细颗粒，可使用小型平铺 SVG/纹理图；不透明度约 0.02–0.04。纹理不接收点击、不遮住照片/文字、不在整屏上运行昂贵滤镜。用页面底面/分区伪元素处理，作品内容表面保持清楚。
- 第二层为整块展区背景，有清晰节奏；不要增加第三层的大面积作品背景图、装饰渐变、漂浮粒子、动态噪点、重阴影或 3D 跟随倾斜。
- 所有工作只在本地预览，不注册 Sites、不上传、不部署、不推送远程。
- 使用 `design-taste-frontend` 与 Sites 本地预览流程时，用户已确认的构图/色彩/双核心优先于技能默认随机方向与单 CTA 偏好；不重新抽签或扩大为复杂滚动场景。浏览器优先 `ego-browser`，先读其技能与实际 `ego-browser skill` 指南。
